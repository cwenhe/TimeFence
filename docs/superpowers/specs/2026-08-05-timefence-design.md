# 时界（TimeFence）Android 应用设计规格

## 1. 项目定位

“时界”是一款本地运行的 Android 应用，用于在用户配置的时间范围内阻止指定应用继续使用。规则开始时，即使目标应用此前已经停留在前台且用户没有进行任何操作，时界也必须主动将其切回桌面；规则生效期间再次打开目标应用时，时界必须立即拦截。

项目目录为 `timefence-android`，Android 应用显示名称为“时界”，初始包名使用 `com.cwenhe.timefence`。

### 1.1 核心目标

- 支持选择一个或多个已安装且可启动的应用。
- 支持配置开始时间、结束时间和每周重复日期。
- 到达开始时间时主动检查当前前台应用，不依赖新的窗口切换事件。
- 规则生效期间持续拦截目标应用，并向用户说明限制结束时间。
- 所有规则仅保存在设备本地，不需要账号、网络或云服务。
- 在荣耀 MagicOS 上明确引导用户完成自启动、后台运行和电池优化设置。

### 1.2 首版不包含

- 远程家长控制、多人共享和云端同步。
- 使用时长配额、网站过滤、位置触发和统计报表。
- 广告、订阅、应用内购买和账号系统。
- 未经设备所有者配置的防卸载、禁止关闭无障碍或禁止强制停止能力。
- iOS、平板专用布局和应用商店发布流水线。

## 2. Android 能力边界

普通 Android 应用不能直接结束其他应用的进程。时界通过 `AccessibilityService` 识别前台窗口，并调用系统全局“返回桌面”动作，使被限制应用立即离开前台；规则有效期间若再次进入，同样会再次被送回桌面。该行为满足“指定应用不可用”，但不声称已经杀死目标应用进程。

以下情况超出普通应用能够可靠控制的范围：

- 用户手动强制停止时界。
- 用户关闭无障碍服务或撤销精确闹钟权限。
- 系统或厂商电池策略禁止时界在后台运行。
- 用户卸载时界或通过受控范围外的系统能力停用它。

应用必须如实展示保护状态，权限缺失时不能继续显示“保护正常”。

## 3. 交互与视觉设计

界面采用 Jetpack Compose 和 Material 3。整体风格安静、清晰、偏工具属性，不使用营销式首页、装饰性渐变或大面积单一色调。基础色使用石墨黑和柔和白，运行正常使用青绿色，正在拦截使用砖红色，权限警告使用琥珀色。卡片圆角不超过 `8dp`。

### 3.1 导航结构

底部导航包含三个入口：

1. **今天**：查看保护状态、当前规则和下一次时间边界。
2. **规则**：查看、新建、编辑、启用或停用规则。
3. **设置**：查看权限、后台运行状态和应用信息。

### 3.2 首次启动

首次启动使用分步权限引导，不用长篇功能说明：

1. 开启无障碍服务，用于识别并退出受限应用。
2. Android 12 及以上开启精确闹钟权限，用于准时处理已在前台的应用。
3. Android 13 及以上开启通知权限，用于展示保护状态和权限异常。
4. 荣耀设备展示自启动、后台运行与电池优化检查入口。

每一步显示当前状态和系统设置按钮。必要权限未完成时可以进入应用并编辑规则，但首页明确显示“保护未就绪”，且不能把规则描述为正在可靠执行。

### 3.3 “今天”页面

页面顶部是紧凑的应用栏，标题为“时界”。其下使用一个全宽状态带展示以下三种状态之一：

- **保护中**：显示当前规则结束时间和正在限制的应用数量。
- **等待中**：显示下一条规则的开始时间。
- **需要设置**：显示缺失权限和直达设置的操作。

状态带下方按时间顺序展示今天的规则列表。每项显示规则名、时间、重复星期、应用图标和启用开关。右下角使用带加号图标的浮动按钮新建规则。

### 3.4 规则编辑页面

规则编辑采用单页表单，字段顺序如下：

1. 规则名称。
2. 开始时间和结束时间。
3. 重复星期，使用七个紧凑的可选日期控件。
4. 受限应用入口，进入可搜索的应用选择页。
5. “生效期间锁定本规则”开关。

保存前必须至少选择一天和一个应用，且开始时间不能等于结束时间。结束时间早于开始时间表示跨越午夜。

### 3.5 应用选择页面

应用列表只展示具有桌面启动入口的应用，不请求 `QUERY_ALL_PACKAGES`。列表支持按应用名搜索，行内展示应用图标、名称和勾选框。时界自身以及会导致设备无法恢复的关键系统入口不可选择。

### 3.6 拦截反馈

检测到受限应用后，时界先执行系统“返回桌面”动作，再通过短时无障碍覆盖层显示：

- 规则名称。
- “已限制到 HH:mm”。
- 关闭提示的图标按钮。

覆盖层不提供“临时解锁”，数秒后自动消失，不长期遮挡桌面。

## 4. 规则语义

规则使用设备本地时区，开始时间包含在有效范围内，结束时间不包含在有效范围内。

- `08:00-10:00` 在 `08:00:00` 生效，在 `10:00:00` 结束。
- `22:00-07:00` 归属于开始日，并持续到下一天 `07:00`。
- 设备时间、日期或时区变化后立即重新计算当前状态和下一次边界。
- 夏令时造成某个本地时间不存在时，在该时间之后的第一个有效时刻触发；时间重复时按第一次出现触发。
- 已卸载应用的包名保留在规则中并标记为不可用；相同包名重新安装后规则重新生效。

“生效期间锁定本规则”只禁止在时界界面内编辑、停用或删除当前规则，不承诺阻止用户关闭系统权限或卸载应用。

## 5. 技术方案

项目采用单 `app` 模块，使用 Kotlin、Jetpack Compose、Material 3、Room 和 Kotlin 协程。首版最低支持 Android 8（API 26），固定使用 `compileSdk 35` 和 `targetSdk 35`。Gradle、Kotlin、Android Gradle Plugin 和第三方依赖在实施计划中锁定具体版本，不使用动态版本。

### 5.1 组件边界

| 组件 | 职责 |
| --- | --- |
| `ScheduleRepository` | 保存规则、应用包名和启用状态，并提供状态流。 |
| `ScheduleEvaluator` | 纯逻辑计算当前有效规则、受限包集合和下一时间边界。 |
| `BoundaryAlarmScheduler` | 使用 `AlarmManager` 注册唯一的下一次精确边界，并在规则变化后重建。 |
| `BoundaryAlarmReceiver` | 在边界到达时唤醒进程、刷新状态并请求前台应用检查。 |
| `BlockAccessibilityService` | 监听前台窗口变化，读取当前活动窗口，在命中规则时返回桌面并显示反馈。 |
| `SystemChangeReceiver` | 在开机、时间、日期或时区变化后重建闹钟。 |
| `PermissionStatusRepository` | 汇总无障碍、精确闹钟、通知和电池策略状态。 |
| Compose 界面 | 展示状态并编辑规则，不直接承担时间计算或拦截逻辑。 |

### 5.2 双触发拦截

时界不能只依赖无障碍窗口事件，而采用两条互补路径：

1. **窗口触发**：目标应用进入前台时，`BlockAccessibilityService` 立即校验当前规则并拦截。
2. **时间触发**：规则保存、启停、开机或系统时间变化后，`BoundaryAlarmScheduler` 计算下一条开始或结束边界，并通过 `setExactAndAllowWhileIdle` 注册精确闹钟。开始边界到达时，服务主动读取活动窗口；即使用户没有触摸屏幕且窗口没有变化，也会发现已在前台的目标应用并返回桌面。

每次边界处理结束后只安排下一条边界，避免为所有历史规则保留大量闹钟。Android 12 及以上使用 `SCHEDULE_EXACT_ALARM` 的用户授权流程，不使用面向闹钟类应用的 `USE_EXACT_ALARM`。

### 5.3 数据模型

规则至少包含以下字段：

- 唯一标识。
- 名称。
- 开始分钟和结束分钟，范围为 `0..1439`。
- 七天重复位集合。
- 受限应用包名集合。
- 是否启用。
- 生效期间是否锁定。

应用名称和图标从 `PackageManager` 实时读取，不复制到规则数据库中作为事实来源。

### 5.4 荣耀设备适配

时界不尝试调用非公开 MagicOS API。设置页根据设备厂商展示荣耀专属检查说明，并优先打开可用的标准系统设置页；无法直达的厂商页面给出明确路径。验收设备上需要确认：

- 允许自启动。
- 允许后台活动。
- 电池优化设置为允许或不限制。
- 无障碍服务保持开启。
- 精确闹钟权限保持开启。

## 6. 异常处理

- 无障碍服务关闭：取消“保护中”状态并给出恢复入口。
- 精确闹钟权限缺失：规则仍可保存，但标记“到点主动退出可能延迟”。
- 闹钟或接收器处理失败：记录本地诊断信息，并重新计算下一边界。
- 数据库读取失败：不执行不确定的拦截，首页显示故障状态。
- 多条规则同时生效：受限应用取并集，反馈采用结束时间最晚的命中规则。
- 已在桌面、系统界面或锁屏：不执行重复返回桌面动作。

日志只记录规则标识、包名、时间边界和权限状态，不采集屏幕内容、输入文字、账号或网络数据。发布构建默认限制日志详细度。

## 7. 验收标准

### 7.1 核心功能

1. 用户可以创建、编辑、启停和删除一条定时规则。
2. 用户可以搜索并选择多个可启动应用。
3. 同日和跨午夜规则在正确的本地时间范围内生效。
4. 规则有效期间打开受限应用，会立即返回桌面并显示结束时间。
5. 规则开始前已打开受限应用，保持画面静止且不进行任何操作，到点后仍会自动返回桌面。
6. 规则结束后可以正常打开原受限应用。
7. 重启手机、修改系统时间或修改时区后，下一条边界被正确恢复。
8. 权限缺失时界面准确显示降级状态，不误导用户。

### 7.2 目标时延

在无障碍服务、精确闹钟和厂商后台权限均正常，且设备未手动强制停止时界的条件下，从规则开始边界到目标应用离开前台的目标时延不超过 1 秒。

### 7.3 验证范围

- `ScheduleEvaluator` 单元测试覆盖同日、跨午夜、跨周、边界包含关系、时区和夏令时。
- 数据库测试覆盖规则和应用集合的增删改查。
- Compose 测试覆盖首页状态、规则校验、应用选择和权限降级提示。
- Android 集成测试覆盖闹钟注册、重建和接收器分发。
- 荣耀真机手工验证静止前台到点退出、重复打开、锁屏唤醒、重启和后台清理场景。
- 每次交付至少运行单元测试、Android Lint 和 Debug APK 构建；有可用设备时再运行仪器测试。

## 8. 交付物

首版交付包括：

- 可在 Android 8 及以上安装的 Debug APK。
- 完整 Android Studio/Gradle 源码工程。
- 权限与荣耀后台设置说明。
- 自动化测试和荣耀真机验收清单。
- 已知系统限制说明。
