# 时界 Shizuku 系统暂停模式设计规格

## 1. 目标与范围

时界保留现有无障碍拦截作为默认保护，并新增可选的“系统暂停模式”。高级模式通过 Shizuku UserService 以 ADB shell 或 Root 身份执行 Android 包暂停命令，使规则内的目标应用停止已有界面并拒绝再次启动。

本次范围包括：

- 规则开始、结束、修改、应用启动、系统时间变化和开机后重新校正暂停状态。
- Shizuku 安装、服务、授权、UserService 连接和命令失败状态展示。
- 关键包保护、暂停所有权记录和“解除全部暂停”紧急入口。
- Shizuku 不可用时停止新增系统暂停，同时继续使用现有无障碍拦截。
- Android 11 及以上的手机端无线调试说明，以及非 Root 设备重启后的恢复说明。

不引入 Device Owner、Root 管理、常驻 ADB 配对服务或远程控制。时界不自动启动 Shizuku，也不绕过系统授权界面。

## 2. 已确认的产品语义

### 2.1 双模式行为

- `无障碍拦截`始终保留：规则生效时检测可见窗口并返回桌面，是默认且无需 Shizuku 的保护方式。
- `系统暂停模式`默认关闭：只有 Shizuku Binder 在线、权限已授予且 UserService 已连接时才能开启。
- 高级模式开启后，当前生效规则内的安全目标包会执行 `pm suspend --user <当前用户> <包名>`；规则失效后执行对应的 `pm unsuspend`。
- 系统暂停成功后，Android 会停止目标应用已有 Activity、隐藏其窗口和通知并拒绝再次启动。不同系统的桌面图标可能消失、变灰或在点击时显示系统提示。
- Shizuku 断开、权限丢失或命令失败时，不开始新的系统暂停；无障碍路径不受影响。

### 2.2 重启与恢复

包暂停状态可能跨手机重启保留，而非 Root Shizuku 服务通常会在重启后停止。因此：

- 时界持久化记录自己已认领并成功请求暂停的包。
- 重启后如果 Shizuku 未运行，设置页显示仍待管理的暂停数量和恢复提示，不假装已经恢复。
- 用户重新启动 Shizuku 后，时界自动重新连接并校正：仍处于规则内的包保持暂停，已离开规则的包立即恢复。
- “解除全部暂停”会先停止高级模式的后续暂停，再恢复所有由时界记录的包；只有全部恢复成功后才清空记录并关闭模式。
- 退出系统暂停模式也必须先完成上述恢复。服务不可用或存在恢复失败时，模式保持开启并显示可重试错误，避免丢失恢复责任。

### 2.3 所有权边界

时界只恢复本地记录为“由时界管理”的包。首次处理目标包时，如果系统已经报告该包处于暂停状态，时界不会认领也不会在规则结束时恢复它。

普通 Shizuku 应用最终共享 ADB shell 身份，Android 没有向多个 shell 工具提供独立的暂停所有权令牌。因此，在另一个工具与时界同时修改同一包、或恰好在命令与本地落盘之间修改状态的极端竞态下，无法做到系统级绝对隔离。实现采用命令前状态检查、同步持久化认领和只处理本地记录三层保护，将影响范围限制到最小。

## 3. 架构与组件

### 3.1 Shizuku 接入

依赖固定为：

```kotlin
implementation("dev.rikka.shizuku:api:13.1.5")
implementation("dev.rikka.shizuku:provider:13.1.5")
```

Manifest 显式声明 `rikka.shizuku.ShizukuProvider`。应用进程通过 Binder 在线、死亡和权限结果监听维护连接状态；不使用已弃用且计划在 API 14 删除的 `Shizuku.newProcess`。

`SuspendUserService` 运行在 Shizuku 提供的 shell/root 进程中，通过 AIDL 暴露单包暂停或恢复命令。命令使用参数数组启动 `/system/bin/pm`，包名和用户 ID 在进入进程前严格校验，命令设置超时、合并标准错误并限制回传文本长度。

### 3.2 暂停协调器

`SystemSuspendController` 是唯一能改变暂停状态的应用进程组件。它使用互斥锁串行处理所有校正，输入为：

- 当前规则快照和日历快照计算出的目标包集合。
- 本地高级模式开关和由时界管理的包集合。
- Shizuku 当前连接状态。
- 动态关键包集合和系统当前暂停状态。

每次校正先恢复“已管理但不再需要暂停”的包，再处理当前需要暂停的包。新目标只有在包名合法、不属于关键包、当前未被其他来源暂停时才被认领并执行命令。已管理但被外部恢复的活动目标会重新暂停。

校正信号使用容量为一的合并队列，避免规则 Flow、Binder 回调和系统广播同时触发重复命令。规则时间计算继续复用 `ScheduleEvaluator` 的左闭右开、跨午夜和日历语义。

### 3.3 持久状态

`SystemSuspendSettingsStore` 使用独立 SharedPreferences 保存：

- `modeEnabled`：高级模式是否启用，默认 `false`。
- `managedPackages`：时界当前承担恢复责任的包集合。

认领包时先同步落盘再执行暂停；命令失败则撤销认领。恢复成功后才移除记录。这样即使进程在命令后被系统终止，下一次启动仍能继续恢复。

### 3.4 关键包保护

`ProtectedPackageResolver` 每次校正动态构建不可暂停集合，至少包括：

- 时界和 Shizuku。
- `android`、System UI、系统设置、权限控制器和包安装器。
- 当前桌面、默认电话应用和电话服务。
- 当前及已安装输入法。

应用选择器复用同一解析器隐藏这些包。远端 UserService 再次执行严格包名校验，形成界面、协调器和命令边界三层防护。

## 4. 状态与错误处理

Shizuku 状态区分：

- 服务未运行或未安装。
- Shizuku 版本过旧。
- 尚未授权或授权被拒绝。
- 正在连接 UserService。
- 已通过 ADB shell 或 Root 就绪。
- UserService 退出、Binder 死亡、暂停失败或恢复失败。

任何远端异常都转换为短中文状态，不在界面或日志展示完整命令输出。单包失败不阻止其他包处理；最终状态保留失败包及操作类型，下一次系统信号或用户重试时继续校正。

## 5. 界面设计

设置页新增“高级拦截”区：

- “系统暂停模式”开关：显示当前模式、Shizuku 后端和风险状态。首次开启弹出确认对话框，说明重启后需要重新启动 Shizuku。
- “Shizuku 服务”行：未安装或未运行时打开 Shizuku；未授权时请求系统授权；已授权但连接失败时执行重连。
- 当前管理数量：明确显示时界当前负责恢复的应用数量。
- “解除全部暂停”按钮：使用恢复图标和危险操作确认对话框，成功后关闭高级模式。
- 紧凑说明：系统暂停可能跨重启保留；Android 11 及以上通常可在手机端通过无线调试启动 Shizuku，Android 10 及以下非 Root 设备需要电脑 ADB。

设置项采用现有 Material 3 列表、开关和图标样式，不新增独立首页或嵌套卡片。错误直接显示在高级拦截区，并通过现有 Snackbar 补充一次性操作结果。

## 6. 数据流

```text
规则/日历/时间边界/开机广播
              |
              v
       ScheduleEvaluator
              |
       当前目标包集合
              |
              v
 SystemSuspendController <---- Shizuku Binder/权限状态
       |              |
       |              +---- ProtectedPackageResolver
       v
 SystemSuspendSettingsStore ---- 本地恢复责任
       |
       v
 ShizukuSuspendGateway -> AIDL -> SuspendUserService -> /system/bin/pm
```

无障碍服务与系统暂停协调器共享规则快照，但彼此不互相等待。即使 Shizuku 链路不可用，无障碍窗口事件和边界补检仍能执行。

## 7. 测试与验收

### 7.1 自动化测试

- 包名校验拒绝空值、命令参数、路径和控制字符。
- 关键包策略始终排除静态关键包和动态桌面、电话、输入法。
- 协调器覆盖首次暂停、规则结束恢复、外部已暂停不认领、已管理包被恢复后重试、关键包过滤和部分失败保留。
- Shizuku 不可用时不执行新暂停；服务恢复后自动校正。
- 退出模式和紧急恢复只在全部包恢复后关闭模式。
- `pm` 命令结果覆盖成功、非零退出、超时和异常。
- 设置页覆盖未授权、服务停止、ADB/Root 就绪、管理数量和解除确认状态。

python3 -m mkdocs build --strict -d /tmp/timefence-docs

### 7.3 真机验收

- 规则开始前将目标应用留在前台，边界到达后系统立即停止其 Activity，桌面再次点击不能进入。
- 同一应用在规则结束后可正常启动。
- 小窗、分屏和普通全屏均执行系统暂停；无障碍服务继续作为失败兜底。
- Shizuku 服务中途停止后不新增暂停，设置页显示准确；重新启动后自动校正。
- 手机重启后先观察待恢复状态，再启动 Shizuku，确认过期规则对应应用自动恢复。
- 桌面、设置、电话、输入法、包安装器、Shizuku 和时界永远不会进入暂停命令。

未连接具备 Shizuku 的荣耀真机时，交付说明必须明确标记真机验收尚未执行，不能用模拟器构建结果代替。

## 8. 不包含的内容

- 自动替用户打开无线调试、完成配对或启动 Shizuku。
- 获取 Device Owner、Root 或永久跨重启权限。
- 暂停未被用户规则选中的应用。
- 对其他 Shizuku 工具提供绝对的系统级暂停所有权隔离。
- 修改或覆盖已有 `v1.1.0` Release。
