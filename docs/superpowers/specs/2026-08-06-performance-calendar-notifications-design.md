# 时界性能、日历与提示设计规格

## 1. 目标与范围

本次迭代解决三个相互关联但边界清晰的问题：

1. 其他应用以荣耀小窗、分屏或悬浮窗口存在时，规则开始边界仍应快速退出已在前台的受限应用。
2. 规则重复方式增加“中国法定工作日”和“中国 A 股交易日”。两者都通过 HTTPS 更新并在设备本地缓存。
3. 每条规则支持自定义拦截提示文本和语音播报。渲染后的文本同时用于拦截浮层和拦截事件通知，系统常驻保护通知仍只展示汇总状态。

本次不增加账号、云同步、使用统计、广告、付费或远程控制。联网只用于获取日历，不上传规则、包名、屏幕内容或使用记录。

## 2. 已确认的产品语义

### 2.1 重复方式

每条规则只能选择一种重复方式：

- `每周`：保留现有周一至周日选择，旧版本规则全部属于此类型。
- `工作日`：按中国法定工作日判断，包含国务院公布的调休上班日；法定节假日不算工作日。
- `交易日`：按上海证券交易所和深圳证券交易所共同开市日期判断，不考虑个股临时停牌；调休周末不因为属于工作日而成为交易日。

规则仍使用设备本地时区，区间左闭右开，跨午夜区间归属于开始日。例如交易日规则 `22:00-07:00` 在交易日晚上开始，并持续到下一个自然日 `07:00`。

### 2.2 提示与语音

每条规则增加以下配置：

- 提示文本，默认值为 `已限制{app}，{until}前不可使用`。
- 是否朗读提示文本，默认关闭。

提示文本支持三个占位符：

- `{rule}`：规则名称。
- `{app}`：被拦截应用的当前显示名称，读取失败时使用包名。
- `{until}`：本次命中的规则结束时间，格式为 `HH:mm`。

设置页增加全局“允许语音播报”开关和语音语言选项：跟随系统、中文普通话、关闭。只有全局开关开启且规则开关开启时才朗读。系统 TTS 可能由厂商引擎联网处理，界面需明确提示；时界自身不上传文本。

## 3. 方案选择

### 3.1 小窗性能

选择“规则快照 + 单消费者合并队列 + 可见窗口状态去重”：

- 规则变更通过 Room Flow 更新进程内快照，窗口事件热路径禁止读取 Room。
- 无障碍事件进入容量为 1 的合并队列，只处理最新窗口状态，避免事件风暴创建无限协程。
- 一次边界补检只扫描一次窗口，并对包名集合统一求值，不为每个窗口重复求值。
- 同一受限窗口已成功返回桌面且仍处于可见状态时不重复执行 HOME；窗口真正离开后再次进入才重新拦截。

只做固定时间防抖会增加到点延迟，只有缓存规则又不能阻止 HOME 反馈环，因此不采用这两种单独方案。

### 3.2 日历更新

采用“版本化远程 JSON + 本地 Room 缓存 + APK 内置兜底”：

- 应用启动、用户手动更新和周期任务会检查日历版本。
- 数据保存到本地后，规则计算只读内存快照，不在无障碍回调中访问网络或磁盘。
- 网络不可用时继续使用最近一次完整缓存；首次安装包内只带已经由官方公告确认的年度数据，尚未发布的年度保持“未知”。
- 数据覆盖范围外的工作日或交易日返回“未知”，对应规则不执行拦截并在首页和设置页显示需要更新的状态，避免使用不确定日期误拦截。

远程文件使用项目维护的 HTTPS JSON 地址：
`https://raw.githubusercontent.com/cwenhe/TimeFence/main/data/calendar/zh-CN.json`。
文件由发布维护流程按公开的国务院及交易所年度公告更新；应用只接受合法 JSON、HTTPS、明确版本号和有效日期范围，单次响应上限为 1 MiB。应用内置同格式文件作为离线兜底。

### 3.3 提示和 TTS

拦截时先生成唯一的 `BlockFeedback`（规则、应用、结束时间和渲染文本），再同时交给浮层、事件通知和 TTS，避免三者选择不同规则。TTS 是服务生命周期内的独立控制器：异步初始化、只保留最新请求、使用 `QUEUE_FLUSH`，失败时降级到文字提示。按“规则 ID + 包名 + 文本”做 10 秒节流。

## 4. 数据模型

### 4.1 规则数据库迁移

Room 从版本 1 升级到版本 2，使用正式迁移，不删除已有数据。`rules` 表增加：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `scheduleMode` | `TEXT` | `WEEKLY` | `WEEKLY`、`CN_STATUTORY_WORKDAY`、`CN_A_SHARE_TRADING_DAY` |
| `notificationMessage` | `TEXT` | 空字符串 | 空值时使用内置默认文本 |
| `speakNotification` | `INTEGER` | `0` | 是否允许该规则朗读 |

现有 `daysMask` 保留，仅在 `WEEKLY` 模式下使用。旧规则迁移后名称、时间、星期、应用集合、启用状态和锁定状态必须完全不变。

### 4.2 日历数据库

新增 `calendar_days` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `date` | `TEXT` | `yyyy-MM-dd`，主键 |
| `isStatutoryWorkday` | `INTEGER` | 是否为中国法定工作日 |
| `isAShareTradingDay` | `INTEGER` | 是否为上交所和深交所共同开市日 |
| `sourceVersion` | `TEXT` | 远程文件版本 |
| `updatedAtEpochMillis` | `INTEGER` | 本地写入时间 |

新增 `calendar_metadata` 表保存当前版本、覆盖起止年份、最近成功同步时间和最近错误信息。应用启动后将数据库内容转换为不可变 `CalendarSnapshot`，规则求值只依赖快照。

### 4.3 应用设置

使用现有本地设置存储保存全局 TTS 开关和语言选择。设置改变后不修改历史规则，只影响下一次拦截。

## 5. 组件与数据流

### 5.1 日历组件

- `CalendarRemoteDataSource`：执行 HTTPS 请求、校验响应大小、版本和日期范围，解析为领域数据。
- `CalendarRepository`：负责内置数据、Room 缓存、版本比较、过期判断、同步结果和内存快照。
- `CalendarSyncWorker`：在网络可用条件下按月运行；应用启动和设置页“立即更新”会触发一次非重复同步。
- `CalendarStatus`：向 Compose 提供当前版本、覆盖范围、同步时间和错误状态。

同步采用替换式事务：新文件完整校验成功后一次性替换对应年份，失败时保留旧缓存。同步过程不触碰规则表。

### 5.2 规则求值

`ScheduleEvaluator` 增加日历快照参数，并区分两类操作：

- `evaluate`：为界面和边界闹钟计算当前规则与下一边界，可查询未来覆盖范围内的日期。
- `evaluateActive`：只计算当前时刻的生效规则和受限包集合，不枚举未来日期，供无障碍热路径使用。

日历日期未知时，相关规则被标记为不可确定；界面展示日历更新警告，拦截服务不使用该规则做 HOME。

### 5.3 无障碍服务

`BlockAccessibilityService` 保留窗口事件和边界主动检查两条触发路径：

1. 事件回调只提取包名和事件类型，写入容量为 1 的最新状态队列。
2. 单一消费者从内存规则快照读取规则，调用 `evaluateActive`，不访问 Room。
3. 边界检查只调用一次 `resolveActivePackages()`，对返回的去重包名集合统一判断。
4. 成功执行 HOME 后记录当前可见拦截状态；相同窗口状态不重复 HOME，检测到窗口离开后清除状态。

窗口事件过滤保留窗口新增、移除、活动和焦点变化，纯边界、层级或标题变化不触发完整规则求值；API 差异通过版本判断处理。

### 5.4 提示和 TTS

- `BlockFeedbackFormatter`：校验长度、替换占位符、生成默认提示文本。
- `ProtectionNotifier`：保留低优先级常驻保护状态通知；增加一次性拦截事件通知，内容使用规则自定义文本。
- `BlockOverlay`：显示同一份渲染文本和关闭按钮，四秒后自动消失。
- `BlockSpeechController`：在服务连接期间管理 TTS 引擎，按冷却键去重；`onDestroy` 必须停止并释放引擎。

通知权限被拒绝、通知渠道不可用、TTS 无引擎或语言不可用时，均不得阻止返回桌面和浮层显示。

## 6. 界面设计

### 6.1 规则编辑

“重复”区域改为互斥分段控件：每周、工作日、交易日。选择每周时显示七个星期按钮，选择另外两种时显示对应的日历说明和当前同步状态。

新增“拦截提示”区域：

- 多行文本输入框，显示默认文本和字符计数。
- 占位符快捷插入按钮。
- 使用当前已选应用名称和结束时间生成实时预览。
- 规则级语音播报开关。

保存校验继续要求名称、有效时间、有效重复方式和至少一个应用；提示文本为空时自动恢复默认文本。

### 6.2 设置页

新增“日历”区域：显示工作日和交易日覆盖年份、最近同步时间、同步失败原因和立即更新按钮。

新增“语音提示”区域：全局开关、语言选择和系统 TTS 设置入口。关闭全局开关不会修改规则级开关。

## 7. 错误处理与隐私

- 首次同步失败但内置数据覆盖当前日期：继续使用内置数据，并显示可恢复警告。
- 缓存过期或日期超出覆盖范围：对应规则显示“日历需要更新”，不执行不确定拦截；每周规则不受影响。
- JSON 校验失败、证书错误、超时、HTTP 错误或数据库写入失败：保留旧快照并记录不含规则内容的诊断信息。
- 网络请求只访问固定 HTTPS 主机，不附带规则、包名或用户标识；日志不保存提示文本和 TTS 内容。
- 自定义提示文本最多 120 个 Unicode 字符，去除首尾空白，禁止写入诊断日志。
- TTS 不强行提高音量，不绕过静音、勿扰模式或系统隐私设置。

## 8. 验收标准

### 8.1 性能

- 在普通全屏、荣耀小窗和分屏场景下，规则开始边界到受限应用离开前台的 p95 延迟不超过 1 秒。
- 连续发送 1000 个窗口事件时，规则读取次数为 0，最多一个事件处理任务在途，待处理状态最多保留一个。
- 同一受限窗口持续可见时 HOME 最多执行一次；窗口离开并重新进入后可以再次执行。

### 8.2 日历

- 旧规则升级后行为与版本 1 完全一致。
- 法定节假日、调休上班周末、普通周末分别得到正确的工作日结果。
- A 股休市日、正常交易日和调休周末分别得到正确的交易日结果。
- 工作日和交易日规则覆盖同日、跨午夜、跨周和结束边界；长假不依赖固定七天扫描。
- 远程同步成功、断网缓存、首次安装内置数据、非法响应和覆盖范围外状态均有测试。

### 8.3 提示与语音

- 自定义文本在浮层和拦截事件通知中保持一致，占位符替换正确。
- 规则级和全局语音开关组合行为正确，同一拦截在 10 秒内只朗读一次。
- 无 TTS 引擎、语言不可用、初始化失败、通知权限拒绝或服务销毁时，视觉拦截仍正常。

### 8.4 工程验证

至少运行：

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew assembleDebugAndroidTest
```

有可用荣耀设备时，补充小窗/分屏到点退出、规则重新进入、TTS 静音和后台回收验收；没有设备时在交付说明中明确记录。

## 9. 不包含的内容

- 港股、美股、期货、个股停牌和券商自定义交易日。
- 通过无障碍读取页面文字或输入内容。
- 远程修改规则、账号同步和云端提示模板。
- 绕过系统静音、勿扰模式或厂商后台限制。
