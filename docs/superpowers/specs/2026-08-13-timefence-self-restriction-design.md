# 时界自限制功能设计规格

## 1. 目标与范围

允许用户在“受限应用”选择页中选择时界自身（包名 `com.cwenhe.timefence`）。当包含时界自身的规则生效且时界位于前台时，应用通过无障碍服务执行一次“返回桌面”，使时界界面暂时不可见；无障碍服务、规则快照、边界闹钟和后台协调器继续运行。规则结束后，时界可以正常打开。

本次不改变 Shizuku 系统暂停的安全边界：时界自身仍属于关键保护包，绝不进入 `pm suspend` 命令。这样可以保证规则在时界被送回桌面后仍能继续计算和在结束边界解除限制。

不包含以下内容：

- 通过 Shizuku 暂停或强制停止时界自身。
- 禁止用户从系统设置关闭无障碍、停止服务或卸载时界。
- 在规则生效期间提供临时解锁入口。
- 修改普通应用、桌面、设置、权限控制器、安装器、电话和输入法的现有保护策略。

## 2. 已确认的产品语义

### 2.1 选择与展示

- 应用选择器继续只查询具有桌面启动入口的应用。
- 关键系统包和动态系统角色继续隐藏。
- 仅移除“当前应用包名”这一项的展示过滤，使时界自身可以搜索、勾选和保存。
- 时界自身的应用名称、图标和包名沿用现有 `PackageManager` 读取逻辑。

### 2.2 无障碍拦截

- 规则评估得到的 `blockedPackages` 可以包含时界自身。
- 无障碍服务解析前台窗口时不再无条件排除自身包名；否则自身规则永远不会命中。
- 命中自身窗口后复用现有 `VisibleWindowBlockGate`、`performGlobalAction(GLOBAL_ACTION_HOME)`、反馈和退避逻辑。
- 返回桌面后，服务仍然存活并继续接收边界和窗口事件；验证任务不能把自身再次返回桌面的反馈事件误判为新的目标窗口。
- 设备锁屏或不可交互时维持现有“不执行返回桌面”的行为。

### 2.3 Shizuku 暂停

- `ProtectedPackageResolver.resolve()` 继续返回时界包名。
- `PackageNameValidator.canSuspend()` 继续拒绝时界包名。
- `ProtectedPackagePolicy` 在系统暂停协调前过滤掉时界自身；因此同一规则可以同时限制普通应用并返回时界界面，但不会暂停时界进程。
- 规则结束时，系统暂停层只恢复它实际认领的普通包，不尝试恢复或操作时界。

## 3. 组件改动边界

| 组件 | 变更 |
| --- | --- |
| `InstalledAppRepository` | 将自身包从“候选应用排除集合”中移出；保留其他保护包。 |
| `ProtectedPackageResolver` | 保持自身在系统暂停保护集合中；必要时拆分“选择器排除集合”和“暂停保护集合”的语义，避免再次误用。 |
| `BlockAccessibilityService` | 允许自身包参与可见窗口解析和拦截；保留服务内部事件去重与系统界面保护。 |
| `VisibleWindowBlockGate` | 若现有行为不足，补充自身窗口与返回桌面后的重试测试；不新增独立状态机。 |
| Shizuku 组件 | 行为保持不变，仅通过回归测试证明自身不会发出暂停命令。 |
| 应用选择/规则界面 | 无需新增 UI 控件；列表自动显示时界，保存校验沿用现有规则。 |

实现优先复用现有接口和状态流，不引入新的权限、依赖或持久化字段。

## 4. 数据流与状态转换

```text
应用选择器查询桌面入口
          |
          v
候选列表包含时界自身
          |
          v
规则保存 -> ScheduleEvaluator -> blockedPackages 包含自身
          |                         |
          |                         +--> SystemSuspendController
          |                               (ProtectedPackagePolicy 过滤自身)
          v
BlockAccessibilityService 解析自身前台窗口
          |
          v
GLOBAL_ACTION_HOME -> 桌面
          |
          v
规则结束 -> blockedPackages 移除自身 -> 不再返回桌面
```

关键状态约束：

1. 未生效：时界可正常打开和使用。
2. 生效且时界在前台：返回桌面一次，后台服务继续运行。
3. 生效且时界不在前台：不执行动作。
4. 生效但无障碍服务不可用：保持现有降级提示，不声称保护可靠。
5. Shizuku 模式开启：自身不进入暂停命令；普通包仍按原策略处理。
6. 规则结束：自身可重新打开，普通包按各自规则恢复。

## 5. 异常与安全处理

- `PackageManager` 查询异常时沿用现有空列表/错误处理，不把自身硬编码成可选项，避免产生不可启动条目。
- 无障碍服务无法取得活动窗口时不执行盲目返回桌面，继续使用现有边界重试。
- 返回桌面失败时允许现有退避逻辑重试，不能清除规则或暂停后台服务。
- 任何系统暂停路径仍以保护包集合和远端包名校验为最终安全边界。
- 日志只记录包名、规则标识和动作结果，不记录页面内容或输入内容。

## 6. 验收与测试矩阵

| 需求/规则 | 测试场景 | 预期结果 |
| --- | --- | --- |
| 自身可选择 | 应用列表含 `com.cwenhe.timefence` 且有桌面入口 | 显示名称、图标和勾选框，可搜索并选中 |
| 关键包仍受保护 | 列表加载包含桌面、设置、权限控制器、安装器、电话和输入法 | 这些包不出现在候选列表 |
| 自身规则命中 | 当前前台窗口为时界，活动规则包集合包含自身 | 调用 `GLOBAL_ACTION_HOME`，产生一次反馈 |
| 不误拦截后台自身 | 活动规则包含自身但前台是桌面或其他非目标应用 | 不调用返回桌面 |
| 返回桌面后不循环 | 自身窗口命中后收到服务/桌面窗口事件 | 现有 Gate 去重和退避生效，不无限循环 |
| 规则结束恢复 | 同一规则在结束边界重新评估 | `blockedPackages` 不含自身，时界可正常打开 |
| Shizuku 安全边界 | 系统暂停模式目标集合包含自身 | `ProtectedPackagePolicy` 过滤自身，不产生 suspend 命令 |
| 远端二次防护 | 直接请求暂停自身 | Gateway/UserService 返回拒绝，不执行 `pm suspend` |
| 普通应用回归 | 规则同时包含自身和普通应用 | 自身走无障碍返回桌面，普通应用保持原有无障碍/Shizuku 行为 |
| 权限降级 | 无障碍服务关闭或设备锁屏 | 不误报“保护正常”，不执行不安全动作 |

自动化锚点至少包括：

- 应用候选过滤单元测试（自身保留、关键包排除）。
- `VisibleWindowBlockGate`/拦截协调逻辑测试（自身命中、去重、规则结束）。
- `ProtectedPackagePolicyTest` 和 `PackageNameValidatorTest` 回归测试（自身仍被系统暂停保护）。
- `ScheduleEvaluatorTest` 增加自身包的生效/结束边界组合。

真机验收需在荣耀设备上确认：时界前台到点返回桌面、服务仍存活、规则结束后可打开；未连接真机时必须明确标记未验证。

## 7. 风险与取舍

- 用户可以在规则生效期间通过系统设置停用无障碍或强制停止时界；这是 Android 普通应用能力边界，本次不扩大权限范围。
- 返回桌面不是杀死进程，时界后台任务仍可能受厂商电池策略影响；设置页继续展示后台运行和无障碍状态。
- 允许自身出现在候选列表会增加误配置概率，因此列表行和规则详情应使用真实应用名称，不能伪装成系统包。

## 8. 完成标准

- 自身出现在可选应用列表并能保存到规则。
- 生效期间前台自身会被送回桌面，后台规则与服务继续运行。
- 规则结束后自身可正常打开。
- Shizuku 从未对自身执行暂停命令。
- 上述自动化测试通过，Debug 构建和 Lint 通过；真机项按实际设备状态报告。
